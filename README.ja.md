# doc-diet 🥗

AI エージェントや Claude にコンテキストとして食わせる知識ファイル（`CLAUDE.md` とか）、使っているうちに際限なく長くなりませんか？

自分が関わっていたプロジェクトでは領域ドキュメントだけで 11 本あって、いちばん大きいものは 4,400 行を超えていました。サブエージェントがちょっとした作業を始めるだけでも、毎回この長い文書を頭から最後まで読まなければならない。起動は遅いし、トークンはだだ漏れでした。

短く削ればよさそうなものですが、いざ要約してしまうと「何が抜けた？」「要約は原本の意図をちゃんと含んでいる？」という不安が残ります。

**`doc-diet` はこの問題のために作りました。**
文書をエージェントが読みやすい 150〜300 行にダイエットしつつ、いつでも原本を辿れるように出典を残します。
原本は 1 バイトも触らず `<name>.record.md` としてそのまま保管し、エージェントが読む短縮版（プラグインの中では head と呼びます）には、各行が原本のどの節から来たかを書いておきます。そのうえで短縮版だけを読んだ新しいエージェントに質問をぶつけて、削って抜けたものがないか実際に確かめます。

## 📦 インストール

プラグインのマーケットプレイスから入れます。

```bash
/plugin marketplace add EpsteinKim/doc-diet
/plugin install doc-diet@doc-diet
```

インストールせずにローカルで試すなら、こう実行します。

```bash
claude --plugin-dir /path/to/doc-diet
```

## ✨ 主な機能

### 1. `split-doc`（文書分割スキル）

Claude に「この文書を分けて」と頼むと、このスキルが動きます。
原本を `<name>.record.md` にコピーしておき、元のファイルの場所には短縮版を新しく書きます。終わると `scripts/verify-split.sh` が走って二つを確認します。バックアップが原本と完全に同じかを `cmp` で突き合わせ、短縮版に書かれたバッククォート付きの名前（ファイル名、関数名、設定キー）が原本かコードに実在するかを grep で探します。AI が存在しない名前をでっち上げていないか見るわけです。

### 2. `/doc-diet:check`（抜けテスト）

短縮版だけを見てエージェントがちゃんと答えられるかをテストするコマンドです。
`doc-tester` という読み取り専用エージェントが短縮版だけを読んで、質問に答えます。答えごとに「短縮版にあった / なかった / 曖昧」を付けてから、ようやく原本（record）とコードを開いて、自分の答えが合っていたか（right / partial / wrong）を採点します。

**使い方:**

```bash
/doc-diet:check docs/agents/billing.md "返金の基準日はいつ？" "請求書を削除できるのは誰？"
```

**結果の例:**

```text
# | question            | in-head | grade | correct answer
1 | 返金の基準日         | in-head | right |
2 | 請求書の削除権限      | not     | wrong | finance 権限のみ (record §14)
What the head should have had: 削除権限のルール
```

質問は自分で渡すか、決定ファイルを指してそこから選ばせることもできます。決定ファイルなしで質問を自動生成するのは 0.2.0 で入れる予定です。

*Tip: 以前 AI が一度間違えたエッジケースを質問にすると、とてもよく効きます。*

### 3. `keep-heads-fresh`（最新化ルール）

決定ファイルが変わったら短縮版も忘れずに追いつくようにする、3 つのルールです。

1. 決定を文書に書いたら、同じターンで短縮版にも反映する。
2. 間違いと分かった判定は、原本から消さずに取り消し線を引く。
3. 短縮版は常に 300 行未満に保つ。

## 🪝 フック（Hooks）

エージェントが作業している裏で、コンテキストを数行差し込んでくれるフックです。ファイルには直接触らず、システムに `node` があるときだけ動きます（なければ何もしません）。

**セッション開始時:**

* プロジェクトに `.record.md` ファイルがあれば、Claude に「短縮版は最後まで読み、原本は `(record §N)` の出典をたどるときだけ grep しろ」と伝えます。これはセッションを開くたびに出ます。
* `CLAUDE.md`、`AGENTS.md`、`.claude/` 以下の文書が大きすぎるのに（既定で 300 行または 30KB 超）バックアップがなければ、「分割してみては？」と提案します。
* ある短縮版を最後にテストしてから、そのファイルに触れたコミットが 5 つ以上たまっていたら、`/doc-diet:check` をやってみてはとそっと知らせます。見るのは短縮版 20 本までです。

**文書が編集された（Edit/Write）直後:**

* 短縮版が行数の上限（既定 300 行）を超えたら知らせます。
* `decisionGlobs` に指定した決定ファイルが編集されたら、このターンで短縮版にもルールを反映するようリマインドします。

「短縮版あり」の案内を除けば、通知はセッションごと、ファイルごとに 1 回だけです。`/doc-diet:check` を実行すると `.doc-diet/last-check.json` にそのときのコミットが書かれ、コミット数のカウントが 0 に戻ります。このファイルはコミットしても gitignore しても構いません。

## ⚙️ 設定（`.doc-diet.json`）

プロジェクトルートに `.doc-diet.json` を作ると既定値を変えられます。すべてのキーは任意で、下は例です（`decisionGlobs` は設定しなければ空です）。

```json
{
  "recordSuffix": ".record.md",
  "maxHeadLines": 300,
  "bigDocLines": 300,
  "bigDocBytes": 30000,
  "docGlobs": [],
  "decisionGlobs": ["docs/decisions/*.md"],
  "measureAfterCommits": 5
}
```

*バックアップのファイル名の規則を変えたいなら、`recordSuffix` を `.history.md` や `.記録.md` にすればいいです。*

## 💡 使ってみて

実際のプロジェクトに入れてみると、領域担当のエージェントが起動時に読む量が **440KB から 70KB 程度にがくっと落ちました。** 時間を測った文書 3 本は、読むのにそれぞれ 2〜5 秒ほどでした。

いちばん役に立ったのは `/doc-diet:check` でした。3 回目のテストで、要約のときに飛んでいた例外が一つと、前日に決めたのに誰も短縮版に反映していなかった決定が一つ見つかりました。`keep-heads-fresh` のルールはその二つ目のせいで生まれました。

**🚨 注意:** 上の時間はエージェントの自己申告です。それに `/doc-diet:check` が調べるのは、こちらが投げた質問についてだけ。短縮版そのものが正しいかは誰も代わりに見てくれないので、結局は開発者が一度はざっと目を通す必要があります。

## 🤔 似たツールとの違い

* `agent-md-refactor`（softaworks/agent-toolkit）: 文書を分けてはくれますが、整理しながら中身を削り、検証はありません。
* `claude-token-diet`（MUKE-coder）: プログラムというより、トークン節約のための設定集に近いです。
* claude-mem、Mem0、Hindsight: 知識文書ではなく、会話の履歴を保存するためのものです。
